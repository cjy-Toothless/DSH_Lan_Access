# ADR 0001：在 DSH 进程内实现局域网反向代理插件

- 状态：已采纳
- 日期：2026-11-11

## 背景

DSH 桌面版只监听 `127.0.0.1` 的随机端口，官方拒绝 `--host 0.0.0.0`；手机浏览器无法直接访问。用户需要一个「插件项目」，在局域网内（手机浏览器）访问电脑端 DSH。

## 可选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. 修改 profile 让 DSH 直接监听局域网 IP | 无额外进程 | 桌面宿主硬编码参数、随机端口，且会让桌面窗口自身连不上；还要手工处理 token/Cookie | 不可行 |
| B. 独立 Node/Go 反代进程（仓库外单独启动） | 与 DSH 解耦 | 需单独守护进程；与 DSH 端口/生命周期同步困难；用户明确要「插件项目」 | 不采用 |
| C. DSH 插件内启动 `node:http` 反代 | 随 DSH 启停、零外部依赖、可复用 DSH 内部服务（`authenticatedUrl`/`webServer`）、可在 DSH 设置页集成 UI | 与 DSH 同进程，插件缺陷可能影响宿主（需严格防御） | **采纳** |
| D. 直接安装社区插件（@smanx/dsh-proxy 等） | 最快 | 第三方未审计代码、功能/UI 不可控；用户要求创建项目 | 不采用，但参考其设计 |

## 决策

采用方案 C，并作以下设计取舍：

1. **零第三方运行时依赖**：手写 HTTP/WS 透传与头改写（约 300 行），只有二维码生成 vendored（MIT）。
2. **复用 DSH 原生认证**：不实现第二套登录，用 `ctx.connection.authenticatedUrl()` 取进程 launch token 自动兑换 Cookie。
3. **固定回环权威**：转发时固定 `Host: 127.0.0.1:3080`，让签名 Cookie 的 audience 不随桌面版随机端口变化。
4. **设置存独立 JSON**：`$DSH_HOME/lan-access/settings.json`；不读写用户的 `cordis.patch.yml`。
5. **v1 免认证**：按用户明确选择实现；总开关 + 常驻风险提示 + 文档警告，认证作为后续迭代。

## 后果

- 正面：安装即用、随 DSH 启停、无额外进程、代码可审计、中文设置页与二维码体验完整。
- 负面：与 DSH 同进程，反代异常必须自行兜底（已做 502/状态错误隔离）；免认证模式不适合不可信网络；DSH 升级若改变 Host/Cookie/信任围栏规则需要回归。
- 后续：访问密码/扫码配对、TLS、按设备撤销、mDNS 域名。
